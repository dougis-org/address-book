## Why

- Problem statement: The repository has no application. Every later feature (auth, MFA, contacts, sharing, import, deploy) needs a running Laravel app, a test harness, and CI to be built test-first.
- Why now: This is the root of the dependency graph. Issues #2 to #8 are blocked until it lands.
- Business/user impact: A single reproducible dev environment, plus a CI gate on every PR, lets all later work follow TDD without per-feature setup.

## Problem Space

- Current behavior: No Laravel app, no composer.json, no CI workflow for the application.
- Desired behavior: `sail up` runs the app against MySQL, `sail artisan test` passes, and CI runs the same checks green on every PR and on main.
- Constraints:
  - Production host (Exact Hosting, cPanel shared) runs **PHP 8.2**, so Laravel 12 (Laravel 13 needs 8.3).
  - Required PHP extensions are confirmed present on the host.
  - Production DB is MySQL; CI and local must use MySQL, not SQLite, to avoid driver drift.
  - Test-driven development is mandatory for all later work.
- Assumptions:
  - The official Laravel 12 starter kits use Fortify and include login, registration (togglable), password reset, email verification and TOTP two-factor authentication with recovery codes (confirmed against the Laravel 12 starter kit docs). Issues #2 to #4 then become mostly *verify and customize with tests*, not build.
  - Livewire starter kit (Livewire 4, Tailwind, Flux UI) is chosen over Inertia (React/Vue/Svelte) to keep the stack PHP-first and the front-end toolchain small.
  - Local PHP and Composer are not installed; all tooling runs through Docker (Sail or a Composer container).
- Edge cases considered:
  - PHP drift between local, CI and host: pinned to 8.2 in composer.json (`config.platform.php`), Sail, and CI.
  - MySQL version drift: Sail and the CI service container use the same major MySQL version (to be matched to the host in design).
  - Starter-kit tests ship as PHPUnit or Pest depending on installer flags: choose Pest explicitly.

## Scope

### In Scope

- Laravel 12 application created from the official Livewire starter kit (non-WorkOS variant).
- PHP 8.2 pinned in `composer.json` and `config.platform`.
- Sail with MySQL for local development; `.env.example` for MySQL.
- Pest (with Laravel plugin) as the test framework; starter-kit tests converted or created as Pest.
- Pint for code style and Larastan for static analysis, with config committed.
- GitHub Actions workflow: PHP 8.2, MySQL service, Composer cache, runs Pint (check mode), Larastan, Pest on PRs and pushes to main; asset build step.
- README with setup and test instructions.
- `.worktrees/` in `.gitignore`.

### Out of Scope

- Customizing auth behavior (registration policy, MFA enforcement, mail): issues #2, #3, #4.
- Contact model or any address-book domain code: #5 onward.
- Deployment workflow: #8.
- Production hosting configuration.

## Risks

- Risk: Starter-kit Flux UI components may include paid ("Pro") components.
  - Impact: Build or UI features could depend on a license.
  - Mitigation: Use only the free Flux component set; verify in design and avoid Pro components.
- Risk: Starter kit generated by the installer assumes local PHP; this machine has none.
  - Impact: Scaffolding step is awkward.
  - Mitigation: Generate the app inside a PHP 8.2 Docker container (or `laravel/installer` via container) and commit the result; documented in tasks.
- Risk: Laravel installer defaults to the newest framework (13), which needs PHP 8.3.
  - Impact: App would not run on the host.
  - Mitigation: Pin `laravel/framework:^12.0` and `php:^8.2` and verify with `composer why-not`; add a CI check that the lockfile resolves on 8.2.
- Risk: MySQL feature or version differences between CI/local and the host.
  - Impact: Migrations pass in CI but fail on the host.
  - Mitigation: Match the MySQL major version to the host's (to be confirmed by the owner).
